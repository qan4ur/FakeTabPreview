# FakeTabPreview

Тестовый плагин для Paper 1.21.7: показывает, как выглядят таб и список игроков
при наведении на пинг, когда игроков много и у них донат-префиксы.

Фейки — **только** записи в табе (`PlayerInfoUpdate`/`PlayerInfoRemove`) и в player sample пинга.
Это не подключения и не сущности: в `Bukkit.getOnlinePlayers()` их нет, писать им, телепортироваться к ним
и т. п. нельзя.

## Быстрый старт

```
faketab fill 60       # плавно заполнить 60% слотов
faketab status        # сколько фейков сейчас / цель
faketab off           # плавно убрать
```

## Как это работает

### Что видит клиент

Таб в Minecraft — это просто список, который сервер присылает клиенту пакетами:

- `ClientboundPlayerInfoUpdatePacket` — «добавь/обнови запись»: UUID, ник, пинг, режим игры,
  отображаемое имя (`displayName`), порядок в списке (`listOrder`), слой скина (`showHat`);
- `ClientboundPlayerInfoRemovePacket` — «убери записи с такими UUID».

Клиенту всё равно, стоит ли за записью реальное подключение. Плагин сам собирает эти пакеты для
выдуманных записей и рассылает их онлайн-игрокам. На сервере при этом нет ни игроков, ни сущностей,
ни соединений — только список записей в памяти плагина.

```
                     ┌──────────────────────── Paper ────────────────────────┐
 консоль ──/faketab──▶ FakeTabCommand ──▶ FakeTabService (цель, ротация)      │
                     │                          │                             │
                     │       NameGenerator ◀────┤────▶ GroupService           │
                     │       (ники)             │      (префикс, порядок,     │
                     │                          │       LuckPerms)            │
                     │                          ▼                             │
                     │                    FakeRegistry ──снимок──▶ PingListener ──▶ пинг в списке серверов
                     │                          │                             │
                     │                          ▼                             │
                     │                    PacketSender ──PlayerInfo пакеты──────▶ таб у игроков
                     └───────────────────────────────────────────────────────┘
```

| Класс | Отвечает за |
|---|---|
| `FakeTabService` | Цель (число фейков), шаги к ней, ротация, вход игроков, выключение |
| `FakeRegistry` | Список активных фейков, уникальность ников, снимок для пинга |
| `PacketSender` | Единственное место с NMS: сборка и отправка пакетов |
| `NameGenerator` | Ники из пула + вариации, без повторов и без совпадений с реальными игроками |
| `GroupService` | Группа новой записи, её префикс (MiniMessage или LuckPerms) и `listOrder` |
| `PingListener` | Добавляет фейков в player sample пинга и, по флагу, в счётчик онлайна |
| `PlaceholderHook` | Плейсхолдеры `%faketab_*%` для PlaceholderAPI (если он установлен) |
| `FakeTabCommand` | Консольная команда `/faketab` и автодополнение |

### Плавное появление и уход

Команды не создают фейков напрямую — они только меняют **цель**. Раз в `batch-interval-ticks`
таймер делает один шаг:

```
1. фейки, у которых истёк connection-period, «выходят» (не больше batch-size за шаг)
2. текущее < цели  →  каждый из min(batch-size, разница) «слотов» входит с шансом join-chance
   текущее > цели  →  каждый из min(batch-size, разница) «слотов» выходит с шансом leave-chance
3. делать нечего   →  выход без аллокаций
```

Из-за шансов фейки заходят неравномерно: на одном шаге никто, на другом сразу двое — как живые игроки.
При настройках по умолчанию (`batch-size: 2`, `join-chance: 0.35`, шаг раз в секунду) это в среднем
~0.7 входа в секунду. `off` так же постепенно опустошает таб, `off instant` убирает всех одним пакетом.

Каждый фейк при входе получает случайное время сессии `connection-period.min..max-minutes`. Когда оно
истекает, фейк выходит, а на его место по тем же шансам потом заходит новый с другим ником.
Общее число держится около цели, но состав постоянно обновляется.

В режимах `on`, `fill` и `schedule` цель считается от слотов: `max-players × % − реальные игроки`, и пересчитывается
при каждом входе/выходе. Зашёл реальный игрок — один фейк плавно уходит, общая заполненность сохраняется.

### Расписание по времени суток

В режиме `schedule` процент слотов берётся из графика `schedule.points`. Раз в `check-interval-seconds`
плагин смотрит на текущее время в поясе `schedule.timezone` и находит значение между двумя соседними
точками линейно: в 19:15 при точках `18:00 → 65%` и `20:30 → 85%` получится 75%. После последней точки
график плавно переходит в первую через полночь. К результату добавляется случайный разброс
`± jitter-percent`, чтобы онлайн не был «ступенькой», а дальше всё как в `fill`: цель = слоты × % − реальные,
и фейки плавно подтягиваются к ней пачками.

```
 %  85 ┤                                   ╭─╮
    65 ┤                              ╭────╯  ╰─╮
    35 ┼╮                       ╭─────╯         ╰──
    15 ┤╰──╮       ╭────────────╯
     8 ┤   ╰───────╯
       └──────┬──────┬──────┬──────┬──────┬──────┬─
            03:00  06:00  12:00  18:00  20:30  22:00
```

### Префиксы и порядок

Все новые фейки получают `groups.default-group` (по умолчанию `default`). Только с шансом
`groups.random-groups.chance` (по умолчанию 8%) фейк получает одну из `random-groups.list` — по умолчанию
`silver` или `platina`, с весами 3:1. Если стоит LuckPerms и `use-luckperms: true`, префикс берётся из
одноимённой группы LuckPerms, иначе из `format` в конфиге. Проверить распределение можно командой
`faketab list`.

`order` группы уходит в `listOrder` записи. Клиент 1.21.2+ сортирует таб сначала по `listOrder`
(больше — выше), потом по scoreboard-команде, потом по нику. У реальных игроков `listOrder` 0, и плагин TAB
сортирует их командами. Если дать фейкам 0, они без команды встанут **над** всеми реальными игроками,
включая админов. Поэтому по умолчанию `order` отрицательный (default −30, silver −20, platina −10):
фейки идут после всех реальных игроков, а между собой — platina, silver, default.

### Ротация

Отдельная ротация пачкой (`rotation`) по умолчанию выключена: её заменяет `connection-period`.
Если включить, раз в `interval-seconds ± jitter-seconds` заменяется доля `fraction` записей сразу.
Новые ники генерируются, пока старые ещё заняты, — один и тот же ник не «перезаходит» мгновенно.

### Вход игрока и выключение

- Зашедшему игроку сразу отправляются все текущие фейки (пачками по 256 записей).
- Если реальный игрок зашёл с ником, который уже занят фейком, фейк заменяется другим.
- При `onDisable` (остановка, `/reload`) таймеры отменяются, а всем игрокам уходит Remove всех фейков —
  в табе ничего не «зависает».

### Пинг в списке серверов

`PaperServerListPingEvent` может вызываться не из главного потока, поэтому `PingListener` читает только
неизменяемый снимок ников, который обновляется после каждого шага. В player sample добавляются фейки
до `sample-size`, а при `add-to-count: true` их число прибавляется к онлайну. Пинг видят все, кто
пингует сервер, включая сайты-мониторинги.

### Velocity

```
клиент ──пинг──▶ Velocity ──(раз в N секунд) RegisteredServer#ping()──▶ Paper
                    │                                                       │
                    └── ProxyPingEvent: подмешать кэш фейков ◀── sample + онлайн
```

Velocity-плагин не знает про фейков сам: он периодически пингует backend, берёт его player sample,
выкидывает из него реальных игроков (по UUID подключённых через прокси) и кэширует результат.
К каждому пингу прокси он добавляет этот кэш. Так фейки видны, даже когда на сервере нет ни одного реального игрока.

## Сборка

Нужен только JDK 17+ для запуска Gradle; JDK 21 и 25 для компиляции Gradle скачает сам (toolchains).

```powershell
.\gradlew.bat build
```

Готовые jar:

| Платформа | Файл | Требования |
|---|---|---|
| Paper | `faketab-paper/build/libs/FakeTabPreview-Paper-1.0.0.jar` | Paper **1.21.7**, Java 21 |
| Velocity | `faketab-velocity/build/libs/FakeTabPreview-Velocity-1.0.0.jar` | Velocity **4.x** (API 4.3.1), Java 25 |

Пакеты отправляются напрямую через NMS (paperweight-userdev, Mojang-маппинги), **ProtocolLib не нужен**.
Обратная сторона — jar привязан к 1.21.7: после обновления Paper его нужно пересобрать
(весь NMS-код в `faketab-paper/.../packet/PacketSender.java`).

## Установка

### Paper
1. Положите `FakeTabPreview-Paper-1.0.0.jar` в `plugins/`.
2. Запустите сервер — появится `plugins/FakeTabPreview/config.yml`.
3. (Опционально) LuckPerms: при `groups.use-luckperms: true` префиксы берутся из одноимённых групп LuckPerms.
4. (Опционально) PlaceholderAPI: появятся плейсхолдеры `%faketab_*%` (см. ниже). Без него плагин работает
   так же, просто без плейсхолдеров.

### Счётчик онлайна в TAB и других плагинах

Фейки не настоящие игроки, поэтому `%online%` в TAB, `%server_online%` из PlaceholderAPI и счётчики
других плагинов показывают **только реальных**. Чтобы счётчик учитывал фейков, поставьте PlaceholderAPI
и используйте плейсхолдеры FakeTabPreview:

| Плейсхолдер | Значение |
|---|---|
| `%faketab_online%` | реальные игроки + фейки |
| `%faketab_fakes%` | только фейки |
| `%faketab_real%` | только реальные игроки |
| `%faketab_max%` | слоты (`max-players`) |
| `%faketab_target%` | текущая цель по фейкам |

Пример для `plugins/TAB/config.yml` (шапка таба):
```yaml
header-footer:
  header:
    - "&7Онлайн: &a%faketab_online%&7/&a%faketab_max%"
```
Плейсхолдеры безопасно вызывать из любого потока: число фейков берётся из готового снимка.

### Velocity
1. Положите `FakeTabPreview-Velocity-1.0.0.jar` в `plugins/` прокси.
2. В `plugins/faketabpreview/config.properties` укажите `backend` — имя сервера из `velocity.toml`.
3. Если на прокси нужен `add-to-count=true`, включите и `ping.add-to-count: true` на Paper:
   прокси считает фейков как «онлайн backend − реальные игроки на нём».

Как это работает: Velocity-плагин раз в `sync-interval-seconds` пингует backend через
`RegisteredServer#ping()` и кэширует его player sample, а в `ProxyPingEvent` подмешивает его к пингу прокси.
MOTD прокси не трогается. Работает, даже когда на сервере нет ни одного реального игрока.

#### Альтернатива без второго плагина
В `velocity.toml`:
```toml
ping-passthrough = "all"
```
Прокси будет отдавать пинг backend-сервера целиком. Минус: MOTD, иконка и версия прокси
заменяются данными backend.

## Команды (только консоль)

Любая подкоманда `/faketab` от игрока, командного блока или RCON отклоняется: «Только консоль.»

| Команда | Что делает |
|---|---|
| `faketab on` | Плавно выйти на `default-percent`% слотов (с учётом реальных игроков) |
| `faketab off` | Плавно убрать всех фейков |
| `faketab off instant` | Убрать всех мгновенно |
| `faketab fill <percent>` | Цель = `max-players × percent% − реальные` (не меньше 0), дробные значения допустимы |
| `faketab schedule` | Режим расписания: процент слотов берётся из суточного графика `schedule.points` |
| `faketab schedule preview` | Показать график по часам: % слотов и примерное число фейков |
| `faketab set <count>` | Фиксированная цель |
| `faketab add <count>` / `faketab remove <count>` | Изменить цель на `count` |
| `faketab rotate now` | Сразу заменить долю `rotation.fraction` фейков |
| `faketab rotate on` / `off` | Включить/выключить периодическую ротацию |
| `faketab speed <batch> <ticks>` | Скорость появления/исчезновения на лету (не сохраняется в конфиг) |
| `faketab status` | Текущее/целевое количество, % слотов, ротация, скорость |
| `faketab list [страница]` | Сколько фейков в каждой группе и список в порядке таба: ник, группа, пинг, когда выйдет |
| `faketab reload` | Перечитать конфиг, текущие фейки сохраняются |

Примеры:
```
faketab fill 75
faketab fill 33.5
faketab schedule preview
faketab schedule
faketab speed 10 5
faketab set 300
faketab list
faketab list 2
faketab off instant
```

В режимах `on`/`fill`/`schedule` цель пересчитывается при входе и выходе реальных игроков
(`spawn.percent-tracks-real-players`). `set`/`add`/`remove`/`off` задают фиксированную цель и выключают
расписание. Чтобы режим включался сам после рестарта сервера, задайте `auto-start: percent` или
`auto-start: schedule`.
Если цель выше `warn-threshold`, в консоль пишется предупреждение, но команда выполняется.

## Конфиг Paper (`config.yml`)

Полный файл с комментариями: [faketab-paper/src/main/resources/config.yml](faketab-paper/src/main/resources/config.yml).
Основное:

```yaml
auto-start: "off"           # "off" | percent | schedule — что включить при запуске сервера
default-percent: 50.0
warn-threshold: 500
schedule:
  timezone: "system"        # или "Europe/Moscow", "Europe/Kyiv"...
  check-interval-seconds: 60
  jitter-percent: 2.0       # случайный ± к проценту при каждом пересчёте
  points:                   # "ЧЧ:ММ" в кавычках → % слотов, между точками — плавный переход
    "00:00": 35
    "06:00": 8
    "12:00": 30
    "18:00": 65
    "20:30": 85
    "22:00": 70
spawn:
  batch-interval-ticks: 20  # шаг раз в секунду
  batch-size: 2             # максимум входов/выходов за шаг
  join-chance: 0.35         # шанс каждого «слота» сработать — фейки заходят неравномерно
  leave-chance: 0.35
connection-period:          # сколько фейк «сидит» на сервере, потом выходит
  enabled: true
  min-minutes: 5
  max-minutes: 25
rotation:
  enabled: false            # замена пачкой; обычно не нужна при connection-period
entry:
  latency: { min: 25, max: 140 }
  gamemode: SURVIVAL
groups:
  default-group: default    # все новые фейки
  random-groups:            # и лишь иногда — редкая группа
    chance: 0.08            # ≈ каждый 12-й
    list: [silver, platina] # можно строкой "silver;platina"
  use-luckperms: true
  list:
    default: { format: "<gray><name>", order: -30 }
    silver:  { format: "<#c0c0c0>[Silver]</#c0c0c0> <white><name>", weight: 3, order: -20 }
    platina: { format: "<gradient:#e5e4e2:#7fd3ff>[Platina]</gradient> <white><name>", weight: 1, order: -10 }
ping:
  enabled: true
  sample-size: 12
  add-to-count: false
```

- `format` — MiniMessage (градиенты, hex), `<name>` заменяется ником.
- `order` — `listOrder` записи в табе: больше — выше. Реальные игроки имеют 0, поэтому отрицательные
  значения ставят фейков после всех реальных игроков (подробнее — в «Префиксы и порядок»).
- `weight` — вес среди `random-groups` (по умолчанию 1).
- Ники: из пула `names.base` с вариациями (`Steve_42`, `xNovax`, `Raven2011`…), без повторов среди
  активных и без совпадений с реальными игроками онлайн. Если игрок зашёл с ником фейка, фейк заменяется.

## Пинг и мониторинги

Фейков в пинге видят все, кто пингует сервер, в том числе сайты-мониторинги. Большинство мониторингов
запрещают накрутку онлайна и банят за неё. Чтобы фейков в пинге не было, выключите `ping.enabled`
(на Velocity — не ставьте плагин или задайте `sample-size=0` и `add-to-count=false`).

## Известные ограничения

- Paper-jar работает только на 1.21.7 (NMS). Velocity-jar — только на Velocity 4.x с Java 25.
- У фейков стандартный скин (по UUID), без текстур.
- С плагином TAB фейки стоят после всех реальных игроков, а не вперемешку с реальными default: TAB сортирует
  своими scoreboard-командами, а у фейков их нет. Если TAB включён в режиме Layout, он сам рисует весь
  таб, и фейки там не появятся.
- Velocity-плагин отделяет фейков от реальных игроков по UUID игроков, подключённых к backend через прокси.
